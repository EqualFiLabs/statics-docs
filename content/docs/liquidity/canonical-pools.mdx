:::warning Release scope
Basket creation and its canonical pools are Phase 2 of the staged Statics Diamond. The historical testnet deployment has older basket pools; the Phase 1 mainnet cut does not install these selectors. Match the ABI and deployment before transacting.
:::

Each basket constituent gets one canonical Uniswap v4 pool against its BasketToken. [Basket creation](/docs/baskets/creation) atomically initializes these pools and supplies the creator-funded launch seed; successful creation makes them immediately available. The creator selects the static native v4 LP fee (0 through 999,999 pips), tick spacing, initial price, and paired-asset budget for each pool.

The separate [Statics public hook fee](/docs/liquidity/swap-fee-hook) charges input and output swap legs and routes the basket allocation profile. Native v4 LP fees belong to ordinary liquidity providers. Basket launch POL and later activated fee inventory use explicit [managed POL](/docs/liquidity/permanent-liquidity) positions under protocol custody; they are not a hook-owned full-range position.

A user can hold an external PositionManager NFT or opt a range into a PositionNFT [gauge](/docs/liquidity/canonical-lp-rewards). Phase 2 also adds typed borrow-to-liquidity paths using basket credit. General [Phase 1 public pools](/docs/liquidity/protocol-pools) use the same public hook and gauge machinery without becoming basket backing or collateral.

When a basket enters its Phase 2 `ExitOnly` state, canonical pool unwind follows the configured lifecycle only after managed POL positions are closed. User-owned v4 principal is not consumed by protocol unwind. Read the deployed basket and pool status before any entry or exit.
