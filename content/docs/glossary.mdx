Short definitions for terms that appear throughout the docs. Linked pages carry the full mechanics.

## Basket and market terms

| Term | Meaning |
| --- | --- |
| **Basket / static basket** | A fixed-composition multi-asset market. Constituents and per-unit bundle amounts are set at creation and do not change. |
| **BasketToken** | The ERC-20 that represents one unit of a basket's fixed bundle. Minting deposits the bundle; redemption returns it (less fees). Not ERC-4626. |
| **Constituent** | One ERC-20 asset inside a basket's immutable vector (up to 16). |
| **Bundle amount** | How many units of a constituent back one full BasketToken (scaled to 18 decimals in accounting). |
| **Genesis basket** | A basket created by protocol governance while public creation is closed (`creationFee = 0`). |
| **Canonical pool** | The single Uniswap v4 BasketToken/constituent pool registered for each constituent at basket creation. |
| **General pool** | A Phase 1 public-hook Uniswap v4 pool between two compatible ERC-20s or native ETH and an ERC-20, with no basket association. Launch configuration opens creation to anyone paying the exact fee. |
| **Protocol pool** | A normalized registered market: either one basket canonical pool or one general pool. |
| **Managed POL** | PoolId-reserved, claim-backed protocol inventory placed into explicit custody-constrained v4 positions by an authorized operator. General pools start with POL disabled. |
| **Bilateral hook fee** | Public-pool swap fee charged on realized input and output by `StaticsSwapFeeHook`, separate from each pool's creator-selected static native v4 LP fee. |

## Accounts and credit

| Term | Meaning |
| --- | --- |
| **PositionNFT (`STXPOS`)** | The shared ERC-721 account. Phase 1 supports STATICS stake, rewards, and managed LP positions; later phases add baskets, loans, and Dollar legs. Transfer moves every active part of the account. |
| **Self-backed lending / basket credit** | Borrowing a basket's proportional constituent vector against deposited BasketTokens at the basket LTV. No price-oracle liquidation; unpaid debt does not create bad debt on other baskets. |
| **STATICS Operator / Genesis NFT** | One of the fixed 5,555 `STATOPS` ERC-721 tokens. “Operator” is the public collection identity; contracts retain the Genesis name. It can be acquired or redeemed through the Vault and later registered, activated, linked, or used for secured credit. |
| **Genesis secured credit** | A post-epoch, fixed-term release of bounded STATICS backing represented by an Operator. It supports additional draws and partial repayment, charges flat native origination/draw and extension service fees, and uses permissionless recovery after maturity plus grace. |
| **Tranche** | An independent loan slice on a position with its own principal vector and maturity. |
| **Recovery** | After maturity and grace, anyone may settle an expired tranche, applying the recovery penalty and splitting a bounty with protocol fees. |
| **Flash composition** | Atomic borrow of a basket's full constituent vector through a typed callback; principal plus fees must return in the same transaction. |

## Statics Dollar

| Term | Meaning |
| --- | --- |
| **Statics Dollar (`USDstx`)** | Senior fungible dollar token minted from configured collateral profiles. |
| **Risk Shares (`ethLEV`)** | Junior, series-scoped claims issued with volatile-profile minting. Recombining equal senior and junior claims returns collateral. |
| **Volatile profile** | Dollar path that mints equal USDstx + Risk Shares against assets such as WETH. |
| **Pegged profile** | Dollar path that mints only USDstx against a pegged collateral (for example, a configured dollar-pegged asset), with separate mint/redeem fees and no Risk Shares. |
| **Senior claim** | The USDstx side of a volatile mint — priority claim relative to Risk Shares under solvency rules. |
| **Dollar Core** | The separate custody and solvency system for Dollar collateral. |

## Lifecycle and governance

| Term | Meaning |
| --- | --- |
| **Active** | Normal basket mode: mint, redeem, borrow, and related flows allowed per facet rules. |
| **Quarantined** | Guardian-restricted mode that blocks new exposure while preserving repay, recover, and exit paths. |
| **ExitOnly** | Wind-down mode that disables new risk in installed facets; required before permanent liquidity can unwind to treasury. |
| **Basket creation policy** | In Phase 2, `creationFee() == 0` limits basket creation to governance; a positive fee allows paid public basket creation. This is separate from public-pool creation. |
| **Public pool creation fee** | `poolCreationFee()` is the exact native payment to create a general pool. The Phase 1 launch configuration sets 0.01 ETH; anyone may create with exact payment. |
| **Asset permissionless** | There is no asset allowlist: creators may name arbitrary ERC-20 addresses. This is **not** the same as open basket creation. Inclusion is not an endorsement. |
| **Timelock** | `StaticsTimelock` delays privileged actions across the phased protocol. |

## Rewards

| Term | Meaning |
| --- | --- |
| **STATICS** | The configured staking token used for global multi-asset reward eligibility. |
| **Global rewards** | Fee shares claimable by positions that stake STATICS and opt into selected reward assets after the eligibility delay. |
| **Range-gauge rewards** | Separately funded rewards for opted-in PositionNFT-managed v4 liquidity, including concentrated ranges; native v4 LP fees remain separate. |
