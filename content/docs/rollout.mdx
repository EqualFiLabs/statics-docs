Statics is permissionless by design and staged in deployment. The contracts implement the full product surface; public access opens in steps as operational confidence grows.

Use this page to separate three clocks:

| Clock | Meaning |
| --- | --- |
| **Implemented** | Present in the deployed contract surface |
| **Enabled now** | Open to ordinary users on the current deployment |
| **Conditional** | Possible when real activity, pricing, and risk conditions allow — never guaranteed |

## Current phase

| Field | Status |
| --- | --- |
| Network | Robinhood Chain Testnet (`46630`) |
| Deployment class | Integration beta — addresses and parameters can change |
| Mainnet | No production Statics deployment is recorded |
| Basket creation | **Protocol-only** (`creationFee = 0` → owner-only genesis) |
| Live basket example | Genesis **TPA1** (tokenized-stock fixtures: TSLA, PLTR, AMD) |

Do not treat testnet fixtures, mock USDG, owner-mintable STATICS, or the short timelock delay as production defaults. See the [deployment snapshot](/docs/reference/robinhood-testnet-deployment) and [security model](/docs/reference/security-model).
:::

## What you can do now

On the integration beta, ordinary users can:

- claim faucet fixtures and [get started on testnet](/docs/start/testnet-onboarding);
- open a PositionNFT and stake `STATICS`;
- mint and redeem the live genesis basket (TPA1);
- swap on TPA1's canonical Uniswap v4 pools;
- deposit basket tokens, borrow self-backed constituent credit, repay, extend, and recover;
- mint pegged `USDstx` against the active Mock USDG profile;
- stake eligible canonical LP positions where configured.

Ordinary users **cannot** create new baskets while the creation fee is zero.

## Who can create baskets

Onchain creation has two modes, switched by `creationFee()`:

| `creationFee()` | Who may create |
| --- | --- |
| **Zero** | Diamond owner only (controlled genesis). Public creation is closed. |
| **Positive** | Any caller that pays the exact native fee. |

There is **no onchain partner role or asset allowlist**. While creation is owner-only, the protocol may still deploy baskets for selected partners through the same genesis path as an operational choice — that is offchain coordination, not a separate contract mode.

See [Basket creation](/docs/baskets/creation).

## Expected basket focus

| Phase | Creation access | Basket focus |
| --- | --- | --- |
| **Initial launch / current beta** | Protocol only | Curated baskets. Testnet uses tokenized-stock fixtures (TPA1); exact launch compositions remain TBD until finalized. |
| **Partner operations** | Protocol deploys for approved partners | Selected partner tokens and configurations, still via owner-controlled creation while the fee is zero |
| **Open creation** | Anyone paying the creation fee | Compatible ERC-20 assets, subject to protocol requirements and token-behavior risk |

Statics is a generic fixed-bundle basket protocol (1–16 ERC-20s), not a stock-only product. Tokenized-stock baskets are the concrete early example.

## Path to open creation

Open (fee-gated) creation is a **parameter change** (`setCreationFee` under governance), not a separate product build. It should enable only when the operators have sufficient confidence in:

- security review and release qualification;
- production staking-token and role configuration;
- economic parameters and monitoring;
- market and operational readiness.

No calendar date is committed in these docs. Treat any external timeline as provisional until governance actually raises the creation fee above zero.

## Implemented but not publicly enabled

These surfaces are in the contracts and may already be usable against **existing** baskets, but are easy to misread as fully public product access:

| Surface | Notes |
| --- | --- |
| Permissionless basket creation | Implemented; **disabled** while `creationFee = 0` |
| Full creator configuration surface | Available to the creating caller when creation is allowed |
| Flash arbitrage receiver | Optional helper for one overpriced path — no profit guarantee |
| Permanent liquidity compounding | Permissionless compound of matched inventory; depth depends on activity |
| Dollar volatile profiles / risk recovery | Implemented; check which profiles are active on the deployment |
| Production immutability | Final cut that removes diamond-cut authority is a later release ceremony |

## Language for outcomes

Prefer conditional wording:

- Additional mint, redeem, and pool paths **may** increase activity when prices diverge.
- Activity **can** generate swap and non-swap fees.
- Fee shares **may** compound into permanent protocol-owned liquidity when inventory matches.
- Self-backed basket credit and Statics Dollar minting are available only within configured risk limits.

Avoid guarantees about volume, rewards, liquidity growth, or peg maintenance.
