## Choose a target first

The recorded Robinhood mainnet Genesis launch is a standalone token, Operators
NFT, vault, and market deployment. It has **no `StaticsDiamond` address**. The
earlier public Robinhood testnet beta has a Diamond for baskets, positions,
Dollar, and lending. Current protocol source contains later APIs that are not
deployed at either of those address sets.

| Target | Chain ID | Address and interface source | Use this guide for |
| --- | --- | --- | --- |
| [Mainnet Genesis](https://github.com/EqualFiLabs/statics/blob/master/deployments/robinhood-mainnet-genesis.json) | `4663` | Genesis manifest and its launch-source commit | Standalone Genesis contracts only; no Diamond or basket-suite ABI |
| [Earlier public testnet beta](/docs/reference/robinhood-testnet-deployment) | `46630` | [Testnet addresses](/addresses.json) and [deployment-pinned ABIs](/abi/index.json) | The basket, position, Dollar, lending, and flash examples below |
| [Later testnet rehearsal](https://github.com/EqualFiLabs/statics/blob/master/deployments/robinhood-testnet-46630-rehearsal-20260903T033729Z.json) | `46630` | Its own disposable deployment manifest | Historical rehearsal only; do not reuse the public beta addresses |
| [Current protocol source](https://github.com/EqualFiLabs/statics) | Depends on deployment | Interfaces from the exact source commit being built; no permanent Diamond deployment recorded | Genesis-to-Diamond integration and general-pool examples below |

For the earlier public testnet beta, `StaticsDiamond` is the basket action
surface, PositionNFT contract, Dollar gateway, Core periphery, fee receiver,
and managed recovery holder. There is no separate user router. Check the
target chain, address, and ABI together before submitting a transaction.

## Disciplines

- **Quote immediately before submission.** Quotes reflect current supply, pool
  state, and health.
- **Pass explicit maximums and minimums** on every value-moving call.
- **Scope approvals to the typed next action.** Reusable allowances are tolerated
  by the permit paths but not required.
- **Reconcile indexed events against current views** after reorgs.

## Earlier public testnet beta examples

These examples illustrate the earlier beta's `StaticsDiamond` flows. Check
each call against the deployment-pinned ABI before use. They are not
instructions for the mainnet Genesis contracts.

### Create a PositionNFT and stake STATICS

```solidity
address[] memory rewardAssets = new address[](2);
rewardAssets[0] = usdg;
rewardAssets[1] = basketToken;

IERC20(staticsToken).approve(staticsDiamond, 100e18);

uint256 positionId = globalRewards.createAndStake{value: creationFee}(
    100e18,
    msg.sender,
    rewardAssets
);
```

`creationFee` is the exact native amount returned by `positionCreationFee()`
(`0.001 ETH` on testnet). The fee forwards immediately to the treasury.

### Mint and redeem a basket

```solidity
uint256 shares = 10e18;
uint256[] memory maxIn = basket.quoteMint(basketId, shares);

for (uint256 i; i < assets.length; ++i) {
    IERC20(assets[i]).approve(staticsDiamond, maxIn[i]);
}
basket.mint(basketId, shares, msg.sender, maxIn);

IERC20(basketToken).approve(staticsDiamond, shares);
uint256[] memory minOut = basket.quoteRedeem(basketId, shares);
basket.redeem(basketId, shares, msg.sender, minOut);
```

### Deposit basket collateral and borrow

```solidity
IERC20(basketToken).approve(staticsDiamond, collateralShares);
basketCollateral.depositBasketCollateral(positionId, basketId, collateralShares);

(uint256 loanId, uint256[] memory principals) = lending.borrow(
    positionId,
    basketId,
    collateralShares,
    msg.sender
);

// Approve the exact stored principal for each constituent before repayment.
lending.repay(loanId);
```

### Mint Statics Dollar from native ETH

```solidity
(uint256 seriesId, uint256 dollarOut, uint256 riskSharesOut) =
    dollarGateway.depositETH{value: 1 ether}(
        msg.sender,
        msg.sender,
        minimumDollarOut,
        minimumRiskSharesOut
    );
```

### Flash-loan a constituent vector

```solidity
(address[] memory assets, uint256[] memory amounts, uint256[] memory fees) =
    flashLender.quoteFlashLoan(basketId, shares);

flashLender.flashLoan(basketId, shares, address(receiver), routeData);
// receiver.onStaticsFlashLoan(...) must return
// keccak256("IStaticsFlashBorrower.onStaticsFlashLoan") and restore principal + fees.
```

## Current-source Genesis integration

The Diamond linkage and batch paths in this section describe current protocol
source. They are not part of the recorded mainnet Genesis address set or the
earlier public testnet beta. Use them only against a deployment with matching
interfaces and a completed Genesis integration handoff.

Genesis is the contract/API name for the **STATICS Operators** collection. It
has a standalone NFT/vault lifecycle and a permanent integration at
`StaticsDiamond`. For a matching full-stack deployment, applications should
discover the `StaticsGenesis`,
`StaticsGenesisVault`, `GenesisActivationRegistry`, and
`GenesisLaunchDistributor` addresses from the matching deployment manifest,
then use `StaticsDiamond` for permanent registration, linkage, rewards, and
the Genesis integration boundary. Use `StaticsGenesisVault` for opening,
drawing, extending, partially or fully repaying, and recovering secured credit;
recovery invokes the
permanent integration boundary as part of settlement.

Current source creates IDs `1..5000` in Vault custody and IDs `5001..5555` in
`StaticsTreasuryVesting`. The latter 555 claims are backed by 99.9M STATICS at
finalization and vest separately from the Doppler-native 100.1M treasury token
schedule. The recorded Robinhood testnet deployment does not include these
standalone launch contracts.

After `genesisIntegrationReady()` is true, an owner can call
`registerGenesis(genesisId)` once. Registration follows ordinary owner-changing
transfers; activation resets on transfer and is distinct from registration.
`linkGenesis(positionId, genesisId)` requires the same actual owner for both
NFTs. While linked, both NFTs are transfer-locked. Approvals do not authorize
linking or unlinking.

Genesis direct rewards remain separate from global PositionNFT rewards. The
single-token and treasury claim paths remain available, and the batch paths are:

```solidity
claimAllGenesisRewards(uint256[] calldata genesisIds, address receiver)
claimAllGenesisTreasuryRewards(address receiver)
```

The owner batch claims both STATICS and WETH for the caller-supplied Genesis IDs
and crystallized prior-owner credits. The caller must own every supplied ID; an
empty array claims only prior-owner credits. It does not enumerate wallet NFTs.
While the launch distributor is active, every claim path lazily harvests before
settlement, and a batch harvests once before transferring each asset at most
once.

For the separate secured-credit flow, use `quoteGenesisCredit`,
`quoteGenesisCreditExtension`, and `quoteGenesisCreditRecovery` immediately
before the corresponding action. `openGenesisCredit(genesisId, principal)`
starts a facility; `drawGenesisCredit(genesisId, amount)` reuses unexpired
capacity; and `repayGenesisCredit(genesisId, amount)` accepts partial or full
repayment from any payer. Origination and draw calls pay the current flat native
origination service fee; extension pays its separate flat fee. The initial
source split sends 10% to permanent Genesis reserve backing and 90% to treasury.
See [Genesis secured credit](/docs/genesis/secured-credit) for lock, pause,
repayment, and recovery semantics.

## Create and discover general pools (current source)

Current source supports permissionless general pools, but the recorded testnet
deployment exposes the earlier governed-pool version. Against a matching future
deployment, call `quotePool(params)` immediately before
`createPool(params, creatorAuthorization)`. The quote provides the sorted
PoolKey, PoolId, normalized price, exact creation fee, and EIP-712 digest.

Index `ProtocolPoolCreated`; do not expect an unbounded pool array. Resolve a
known PoolId with `protocolPool`, `isProtocolPool`, `protocolPoolCreator`, and
`protocolPoolFeeRate`. Pool creators claim the fixed 5% bilateral-fee credit
with `claimCreatorRevenue(asset, receiver, minReceived)`. See
[General protocol pools](/docs/liquidity/protocol-pools).

## Failure conditions

The flows above are illustrative. Read the target deployment's interfaces for
complete structs, approvals, return values, and failure conditions. Common
revert causes include:
stale quotes, exceeded per-asset bounds, missing or insufficient approvals,
deferred health exits, lifecycle restrictions (Quarantined / ExitOnly), and
inbound/outbound tax on incompatible tokens.
