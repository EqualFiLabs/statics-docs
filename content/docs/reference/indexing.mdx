Statics state is best indexed from events, then reconciled against current view
calls. Because the chain may reorg, an indexer should treat events as hints and
authoritative views as truth.

## Event surface

Each module emits events for its value-moving actions: basket creation, mint and
redemption, collateral deposit and withdrawal, lending borrow/extend/repay/
recovery, flash loans, global stake and reward opt-in/out, protocol-pool LP stake/
unstake, dollar mint/recombine/pegged mint/redeem, Risk liquidity and incentive
funding, governance lifecycle transitions, and swap-fee hook settlement.

:::note
Use the generated ABIs in [`@statics-protocol/sdk`](/docs/reference/sdk) to
decode event topics and payloads exactly. Event signatures must match the
deployed facet bytecode; do not hand-encode them.
:::

## Suggested read models

| Model | Keyed by | Backed by |
| --- | --- | --- |
| Position | `(chainId, StaticsDiamond, positionId)` | `positionState`, `isLegActive`, `IPositionOwnerIndex` enumeration |
| Basket | `basketId` | basket config, supply, backing, reward state |
| Loan tranche | `loanId` | stored principal vector, maturity, lock state |
| Dollar series | `(profileId, seriesId)` | series state, Risk liquidity, incentive reserves |
| Custody | `token` | `globalReservedByToken`, per-account reservations |
| Genesis | `(chainId, StaticsGenesis, genesisId)` | ownership/lock state, registration, activation, direct reward views, and `genesisOwnerClaimable` |
| Protocol pool | `(chainId, StaticsDiamond, poolId)` | `protocolPool`, creator, PoolId-local fee rate, class allocation, hook POL, and v4 state |
| Creator credit | `(chainId, StaticsDiamond, creator, asset)` | creator revenue accrual/claim events and current credit views |
| Treasury vesting | `(chainId, vesting contract)` | native token schedule, released Operator range, recipient, and releasable amounts |

The PositionNFT owner index (`positionCount`, `positionsOfOwner`) lets an indexer
enumerate a wallet's current positions without scanning every transfer event;
call `syncPositionOwnerIndex` for any legacy position not yet migrated.

## Reorg-safe indexing

1. Index events into a trailing window behind the chain head.
2. On every update, reconcile derived state against the corresponding view call.
3. Treat a view call as authoritative when an event and the view disagree.
4. Re-run the affected read model after any reorg boundary.

## Measured receipts matter

Inbound accounting credits measured receipts, not requested amounts, and several
flows route *actual* (measured) excess rather than quoted amounts — notably flash
loans and extension payments. An indexer that assumes the quoted amount equals
the moved amount will drift on fee-on-transfer tokens. Always reconcile against
the view that reports the stored post-state.

## No background execution

No keeper runs automatically. Lifecycle transitions, recovery, compounding,
treasury distribution, and ExitOnly unwind only advance when a transaction is
submitted. An indexer should not assume time-based state changes; it should
reflect state only after the confirming event is finalized.

## Genesis event and claim handling

Index `GenesisRegistered`, `GenesisLinked`, `GenesisUnlinked`,
`GenesisWeightChanged`, `GenesisActivated`, `GenesisActivationReset`,
`GenesisPurchased`, `GenesisRedeemed`, `GenesisCreditOpened`,
`GenesisCreditDrawn`, `GenesisCreditExtended`, `GenesisCreditRepaid`,
`GenesisCreditRecovered`, `CreditIncreasesPausedSet`,
`RevenueAccrued`, `GenesisRevenueAccrued`, `GenesisRewardsClaimed`,
`GenesisOwnerRewardsClaimed`, and `GenesisTreasuryRewardsClaimed`. A batch claim
is caller-supplied and does not imply owner-wide enumeration. Reconcile emitted
per-token claims against the batch return values and the current reward views;
duplicate IDs are safe but should not be counted twice by an offchain aggregate.

Genesis reward books are distinct from global PositionNFT reward books. On an
owner-changing transfer, settle the previous owner's attributed reward credit,
reset activation, and follow future direct weight under the new owner. Recovery
has the same settlement boundary while also removing the recovered Genesis link
and boost.

## Protocol-pool discovery

For current source, index `CanonicalPoolInitialized` and `ProtocolPoolCreated`
as the two pool-discovery roots. Follow `ProtocolPoolFeeRateSet`,
`BasketFeeAllocationSet`, `GeneralFeeAllocationSet`, `PoolCreationFeeSet`,
`PoolCreationNonceInvalidated`, `CreatorRevenueAccrued`,
`CreatorRevenueClaimed`, `GeneralPoolDecommissioned`, LP staking/reward events,
and hook permanent-liquidity events.

The PoolKey does not encode the creator or bilateral Statics fee rate. Preserve
those fields from `ProtocolPoolCreated` and reconcile them with bounded views.
General pools have no basket association and no basket-staker reward book.
Treat the current-source event schema as distinct from the earlier governed-pool
schema in the deployment-pinned ABI.

## Launch and vesting events

The Operators constructor uses two ERC-2309 `ConsecutiveTransfer` batches,
rather than 5,555 individual mint events. Index the Vault range `1..5000` and
treasury-vesting range `5001..5555` from those batches, then follow
`TreasuryVestingBootstrapped`, `GenesisReleased`, `WithdrawalRecipientUpdated`,
and the Doppler token's `TokensReleased`. `GenesisReleased` reports an inclusive
ascending range and cumulative released count.
