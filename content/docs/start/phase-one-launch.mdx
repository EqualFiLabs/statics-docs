The standalone **STATICS Genesis system is already live on Robinhood mainnet**. Phase 1 is the first deployment of the separate `StaticsDiamond`; it does not redeploy Genesis. The protocol source implements four staged cuts. Availability on a particular chain depends on its verified deployment and active selectors, not on code being present in `master`.

:::warning Deployment status
This site does not yet publish a verified Robinhood mainnet Phase 1 Diamond address or matching Phase 1 ABI. The [historical testnet address set](/docs/reference/robinhood-testnet-deployment) belongs to an earlier, different release. Do not send Phase 1 calls to that address set because a page describes the current source.
:::

## In the Phase 1 cut

| Surface | What it enables |
| --- | --- |
| [Public pools](/docs/liquidity/protocol-pools) | Curated creation initially, with a separate fee switch for later open creation; ERC-20/ERC-20 and native ETH/ERC-20 pairs, creator-selected static v4 LP fees, bilateral hook fees, and optional managed POL. |
| [Permissioned venues](/docs/liquidity/permissioned-pools) | Governance-created pools with creator-authorized terms, a separate hook, venue controllers, trusted router, and non-transferable approved LP positions. |
| [PositionNFTs](/docs/core/position-nft) and [global staking](/docs/rewards/global-rewards) | Transferable accounts, raw STATICS stake, reward-asset selection, eligibility, and claims. |
| [Range gauges](/docs/liquidity/canonical-lp-rewards) | PositionNFT-managed v4 liquidity, native LP fees, protocol STATICS incentives, four direct-funded reward slots, allocator rewards, and claims. |
| [Managed POL](/docs/liquidity/permanent-liquidity) | Claim-backed inventory and explicit custody-constrained position management outside the swap callback. |

Phase 1 also includes timelocked configuration, guardian stops, treasury accounting, creator revenue, reward restrictions, bounded market views, and atomic reward batches. See the [protocol's accepted launch plan](https://github.com/EqualFiLabs/statics/blob/master/docs/adr/staged-phase-one-launch.md) for the exact selector and audit boundary.

:::note Creation policy
The initial general-pool creation fee is zero. Here, **zero means Diamond-owner-only creation**; it does not enable free public creation. A positive fee enables exact-fee public creation. Permissioned pool creation remains a timelocked governance action with creator authorization.
:::

## Before using a deployment

1. Obtain the network-specific deployment manifest and ABI for the exact release. The testnet snapshot is a separate integration reference.
2. Verify the Diamond address, installed selector routes, phase, hook and manager dependencies, and governance configuration against that manifest.
3. Read current onchain fees, pool state, and reward configuration immediately before preparing a transaction. Use `quotePool(params)` before public-pool creation.
4. Treat rewards, POL growth, and trading volume as outcomes of actual funding and activity. No keeper or market activity is automatic.

The [integration guide](/docs/reference/integration) distinguishes Phase 1 paths from later-phase examples. The [rollout page](/docs/rollout) tracks the separate Genesis, protocol, and historical testnet contexts.
